Spotify connection and player

Spotify connection has two parts: you approve access once, then the app asks our server to check or control playback. The server makes Spotify requests for the signed-in account. Spotify credentials stay on the server; the app never receives them. The app sends playback controls and displays track information, but it does not carry or play the audio itself.

What happens when you connect

  1. You tap Connect Spotify in the app. The app sends a signed-in request to POST /api/spotify/connect/.
  2. The server creates two short-lived values for this attempt: a random state value and a private verifier. It saves a one-way fingerprint of the state (a hash) and an encrypted copy of the verifier, tied to your Exercise Plus account. They expire after five minutes. State lets the server check that the person returning from Spotify is finishing the same connection that was just started.
  3. The server creates a Spotify authorization link and sends it to the app. It includes a PKCE challenge (“P-K-C-E”): a scrambled version of the private verifier. Spotify receives the challenge, while the server keeps the original verifier. This proves that the callback belongs to the connection request without putting the private verifier in the link.
  4. The app opens Spotify’s sign-in page. Spotify asks you to approve two permissions: reading playback status and controlling playback. These are called scopes—the specific access you are granting.
  5. After approval, Spotify sends the browser back to /api/spotify/callback/ with a short-lived authorization code and the state value. The server checks that the state matches an unexpired connection for your account, then consumes it so it cannot be reused.
  6. The server sends Spotify the authorization code and the private verifier. Spotify returns an access token, which allows requests for a limited time, and a refresh token, which lets the server obtain a new access token later. The server encrypts both before saving them against your account.
  7. The browser shows whether the connection succeeded and provides a link back to the app. The app refreshes its connection status.

Why keep the encryption key stable? SPOTIFY_TOKEN_ENCRYPTION_KEY is the server-only key used to lock and unlock the saved Spotify tokens. Keep it in Heroku’s protected configuration and back it up securely. If you replace it, the server can no longer unlock existing tokens; users will need to connect Spotify again.

What happens when you use the player

The app sends GET /api/spotify/player/ to read the current player, or sends POST /api/spotify/player/ with an action of play, pause, next, or previous. The request includes the Exercise Plus sign-in token; that token proves who is making the request and is separate from the Spotify credentials.

The server unlocks your Spotify access token and asks Spotify for the playback information or control. If the access token is about to expire, the server refreshes it first. If Spotify rejects a request because the token expired, the server refreshes once and retries. Spotify’s reply is reduced to information the app needs: whether music is playing, the track and artists, its artwork and Spotify link, whether a playback device is active, and any controls Spotify has disabled.

Playback controls require Spotify Premium and an account that Spotify allows to use this app. Spotify also needs an active device for the account; if it reports no device, open Spotify and start or resume playback on that account first. Exercise Plus does not stream music, expose Spotify tokens, or send your Spotify credentials to the phone app.

Server settings this feature needs

  • SPOTIFY_ENABLED=true
  • SPOTIFY_CLIENT_ID and SPOTIFY_CLIENT_SECRET from the Spotify developer app. These identify Exercise Plus to Spotify; keep the secret on the server.
  • SPOTIFY_REDIRECT_URI set to the exact HTTPS address https://<your-app-host>/api/spotify/callback/, also entered in the Spotify developer app.
  • A valid, stable SPOTIFY_TOKEN_ENCRYPTION_KEY used only by the server.
